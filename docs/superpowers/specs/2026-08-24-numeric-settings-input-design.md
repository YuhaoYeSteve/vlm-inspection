# 数字设置输入与并发上限设计

## 背景

设置页目前在数字输入框的 `onChange` 中立即执行 `Number(value)`。用户清空输入框时，空字符串会立刻变成 `0` 并被受控输入框回填，导致无法自然地删除旧值后键入新值。与此同时，并发数在前端、API schema 和任务执行器中都被限制为 1–5。

## 目标

- 并发数、超时和自动重试三个输入框都允许清空后直接重新输入。
- 任意数字输入框为空时，不允许执行“测试并保存”。
- 并发数有效范围调整为 1–500。
- 超时有效范围保持 1–600 秒。
- 自动重试有效范围保持 0–5，且 `0` 是有效值。
- 前后端和任务执行器采用一致的并发范围。

## 非目标

- 不改变默认并发数 3。
- 不改变超时、自动重试的默认值或有效范围。
- 不增加自动纠正、自动补零或失焦回填行为。
- 不改变任务创建时保存模型参数快照的机制。

## 方案

### 前端状态

保留现有 Ark 设置对象作为已解析设置，并为三个数字字段维护可为空的字符串草稿值。服务端设置加载完成时，将数字转换为字符串填入草稿；用户编辑时原样保存输入字符串，因此清空后保持为空，不会立即变成 `0`。

选择字符串草稿而不是 `number | null`，是为了让输入过程与最终 API 数据分离，避免把暂态空值放入要求完整数字的 `ArkSettings` 类型。也不改用非受控表单，以保持现有 React Query 和表单状态结构。

### 校验与提交

三个输入框继续使用数字输入控件，并限制为整数。提交前统一执行以下检查：

1. 任意草稿为空时，“测试并保存”按钮禁用，保存与连接测试都不会发起。
2. 非整数或超出范围时，不调用 API，并显示对应字段的错误信息。
3. 全部有效时，将草稿转换为数字，与其余 Ark 设置合并后保存；保存成功后继续执行现有连接测试。

清空后重新输入有效值，按钮恢复可用。自动重试的字符串 `"0"` 不视为空值。

### 后端与执行器

将 `ArkSettingsWrite.concurrency` 的上限从 5 调整为 500。任务执行器的构造参数校验，以及从任务快照读取并发数时的范围校验，也同步调整为 1–500。这样设置保存、任务快照和实际 worker 数量不会出现边界不一致。

### 错误处理

- 并发数错误：提示必须为 1–500 的整数。
- 超时错误：提示必须为 1–600 的整数。
- 自动重试错误：提示必须为 0–5 的整数。
- 后端仍保留最终边界校验，防止绕过前端提交非法值。

## 测试策略

按测试驱动方式补充回归覆盖：

- 前端测试先复现三个数字字段清空后被回填 `0` 的问题。
- 验证任意字段为空时按钮禁用，保存和测试接口均未调用。
- 验证清空后可以直接键入新值，`500` 可提交，`0` 可作为自动重试值提交。
- 验证并发数 `501`、非法超时和非法重试在前端被拒绝。
- 后端验证并发数 `500` 被接受、`501` 被拒绝。
- 执行器验证构造参数和任务快照都采用 1–500 的边界。
- 运行前端相关测试、后端相关测试、完整构建与测试套件。

## 验收标准

1. 用户可以用退格键彻底清空三个数字输入框，不会自动出现 `0`。
2. 任意数字输入框为空时，“测试并保存”不可用，且没有保存或测试请求。
3. 用户可直接输入并保存并发数 `500`，但不能保存 `501`。
4. 自动重试可保存为 `0`。
5. 实际任务执行使用任务快照中的并发数，最大允许 500。
