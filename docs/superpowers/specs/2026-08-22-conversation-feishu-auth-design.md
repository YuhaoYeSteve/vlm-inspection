# 对话授权驱动的飞书报告集成设计

## 目标

Seed 巡检台不再要求用户在网页中填写飞书 App ID、App Secret、文件夹 Token 或 OAuth 回调地址。用户只需在 Codex 对话中完成一次飞书用户授权，巡检台即可读取该授权状态，并把每次巡检报告创建到指定参考文档所在目录。

本机已解析的目标目录为“我的空间 / 示例目录 / 巡检报告”。实际参考文档 URL、目标目录 Token 和展示路径保存在本机 `.env` 中，不提交到 Git。

## 方案选择

采用 `lark-cli` 用户身份桥接：FastAPI 通过无 shell 的子进程调用 `lark-cli --as user`，由 `lark-cli` 统一保管和刷新 OAuth 凭证。巡检台不读取、复制或保存 access token、refresh token、App Secret。

未采用以下方案：

- 复制 `lark-cli` 凭证到巡检台钥匙串：会形成两套令牌生命周期和安全边界。
- 使用机器人身份创建报告：当前机器人无权访问目标目录，且文档归属与用户预期不符。
- 保留网页 OAuth：仍要求用户理解 App ID、App Secret 和回调配置，违背零配置目标。

## 后端架构

### CLI 执行边界

新增一个专用的异步 `LarkCliRunner`：

- 使用 `asyncio.create_subprocess_exec` 传递参数，禁止 shell 拼接。
- 强制 `--as user --format json`，并关闭 CLI 更新提示，保证 stdout 可解析。
- 对状态查询和写操作分别设置超时。
- 只接受成功信封 `ok: true`；错误信封转换为现有报告错误类型，但不记录令牌或敏感命令输出。
- `lark-cli` 不存在、登录失效、权限不足和网络异常分别返回可读错误码。

### 授权状态

`GET /api/auth/feishu/status` 改为读取 `lark-cli auth status --json --verify`，响应包含：

- 是否已连接；
- 当前用户名称；
- 当前飞书应用名称；
- 身份类型（固定为用户身份）；
- 令牌有效期；
- 目标目录展示路径；
- 参考文档 URL。

只有用户身份为 `ready`、服务端验证通过、令牌有效且具备文档创建、写入和媒体上传权限时，才视为可生成报告。

原网页 OAuth 的开始、回调和断开入口不再由前端使用。现有代码可在本次改造中移除注册，避免误导用户产生第二套授权。

### 报告写入

新增实现现有 `FeishuClientProtocol` 的 `LarkCliFeishuClient`。它通过 `lark-cli api` 继续调用现有 Docx 创建块、写文本块、创建图片块和媒体上传接口，因此保留当前报告结构、操作游标、幂等键和中断续传语义。

目标目录从本机运行配置注入 `ReportBuilder`，不再从网页提交的飞书设置读取。媒体上传通过 CLI 支持的标准输入传递图片字节，不暴露绝对文件路径，也不创建额外临时文件。

## 任务状态修复

当前问题来自任务先进入 `exporting`，再发现飞书不可用后静默返回。改造后：

1. 图片处理完成后，任务先进入 `review_required`。
2. 若 CLI 授权和目标目录均可用，自动创建导出记录；只有创建成功后才进入 `exporting`。
3. 若未授权，任务保持 `review_required`，界面显示“等待飞书授权”，不再显示虚假的“生成报告中”。
4. 启动恢复会把“状态为 exporting 但没有运行中导出记录”的孤儿任务恢复为 `review_required`。
5. 本次改造完成后，对当前卡住任务执行一次报告生成，继续使用已有巡检结果，不重新调用视觉模型。

## 设置页设计

飞书报告区域改为只读状态卡，不包含任何文本输入框：

- 已连接账号：动态显示用户名称；
- 授权方式：显示“Codex 对话授权”；
- 飞书应用：动态显示应用名称；
- 报告位置：显示目标目录完整路径；
- 参考文档：显示可点击链接；
- 授权状态：已连接、未授权、授权过期、权限不足或 CLI 不可用；
- 操作：仅保留“刷新状态”。未授权时提示用户在 Codex 对话中说“授权飞书”。

巡检台不提供“断开”按钮，避免退出共享的 `lark-cli` 登录态而影响其他对话任务。

## 本机配置

新增以下非密钥运行配置，实际值仅写入被 Git 忽略的 `.env`：

- `VLM_FEISHU_REFERENCE_URL`
- `VLM_FEISHU_PARENT_TOKEN`
- `VLM_FEISHU_PARENT_LABEL`
- `VLM_LARK_CLI_PATH`（默认自动从 PATH 查找）

`.env.example` 仅说明字段用途，不包含用户的文档 URL 或目录 Token。

## 错误处理与可观察性

- 报告状态保存最后一个明确错误码，如 `lark_cli_missing`、`feishu_user_not_connected`、`feishu_scope_missing`、`feishu_command_timeout` 或 `report_export_failed`。
- 前端把错误码转换成可执行提示，不显示原始令牌、命令参数或完整上游响应。
- 每个导出步骤继续在 SQLite 中记录完成游标，失败后从未完成步骤续传。
- 状态查询不得把 CLI 的 access token、refresh token 或 App Secret 写入日志、数据库或 API 响应。

## 测试与验收

后端测试覆盖：

- CLI 状态信封解析和必要权限判断；
- CLI 缺失、用户未登录、令牌无效、超时和权限不足；
- 文档创建、文本块、图片块及媒体上传的 argv 和响应解析；
- 无授权时任务停在 `review_required`；
- 孤儿 `exporting` 任务启动恢复；
- 已授权时自动导出仍可续传且不重复创建文档。

前端测试覆盖：

- 设置页不再渲染 App ID、App Secret、文件夹 Token、OAuth 回调输入框；
- 展示连接账号、应用、目标路径和参考文档；
- 未授权及权限不足时显示对话授权提示；
- 刷新按钮重新查询状态。

最终手工验收：重启本地服务，确认当前用户授权仍有效；恢复现有卡住任务；在目标目录生成一份包含 12 张巡检图片和结果的飞书报告；打开返回链接核对目录、计数、文本和图片。
